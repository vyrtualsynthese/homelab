# W5 — Platform Upgrades Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the cluster from K3s 1.30.1 and Traefik 2.10.7 (chart `25.0.3`, already this repository's release) to K3s 1.36.6 and Traefik v3 (chart `42.4.1`, Traefik 3.7.19), through a procedure whose one
unrecoverable step, the etcd restore, is proved before the first node moves, with the same ACME
certificate and no unplanned ingress outage.

**Architecture:** Traefik leaves the K3s bundled addon and becomes an official-chart workload owned by this repo, first at 2.11 (which serves both CRD API groups, so routing never goes blind), then the CRDs are renamed to `traefik.io/v1alpha1`, then Traefik goes to v3. Only after that does K3s move, one minor at a time, servers one at a time. The one step with no way back, restoring etcd, is proved first on a single-node
K3s in WSL2 on the workstation; the Traefik steps ran live, guarded by a schema comparison and the
certificate digest, because a lookalike cluster could not have proved the one file that has no lock.

**Tech Stack:** K3s (embedded etcd), Traefik official Helm chart, System Upgrade Controller, argon2 for the dashboard.

**Spec:** `docs/superpowers/specs/2026-11-10-homelab-stabilisation-design.md` §9 W5

## Global Constraints

- **etcd quorum is two of three.** Never upgrade, reboot or restart two control-plane nodes at once. Order: `nuc0`, `rbp2`, `streaming`. `nas` is the agent and goes last.
- **Never let `channel: stable` run.** Every step sets an explicit version. Re-taken 2026-11-21: `stable` is `v1.37.2+k3s1` and the `v1.36` channel is `v1.36.6+k3s1`. `channel: stable` would skip to 1.37 and bypass the intermediate minors; pin the patch from the minor channel.
- **The ACME certificate must survive.** Reuse the existing `pvc-traefik-nfs` claim. Let's Encrypt allows five duplicate certificates per week and a re-issue wastes them.
- **Both CRD API groups are installed.** 2.11 reads `traefik.containo.us` and `traefik.io`; v3 reads only `traefik.io`. The rename therefore happens while on 2.11, never during or after the v3 step.
- Files under `cluster/argocd/**` are **CRLF**. Any bulk edit must preserve them.
- The builder has no cluster write access. Every cluster-side step is a runbook the operator executes, ending in a verification to paste back.
- **Backups exist, but no etcd restore has been drilled.** The restic jobs cover application data, not etcd. Take an etcd snapshot on a node before every production step and copy it off the node.

## Review Focus

1. **Two servers upgraded at once loses etcd quorum.** Task 10–12 have a strict order and a hard "stop after one node" rule.
2. **A re-issued certificate burns the weekly duplicate limit.** Task 6 verifies the certificate serial before and after; a changed serial means a re-issue and must be investigated, not accepted.
3. **v3 silently drops `traefik.containo.us` resources.** Task 7 fails the plan if any `containo.us` object remains; Task 8 refuses to run until that count is zero.
4. **A bulk grep-and-replace corrupts the CRLF files under `cluster/argocd/**`.** Task 7 uses a script that preserves line endings and verifies with `file`.
5. **A snapshot nobody has restored is not a backup.** The climb has no downgrade: the way back is
   `--cluster-reset` from a snapshot, and that procedure has never been run here. Task 3 proves it once,
   on a single throwaway server, and writes the runbook. Rehearsing the cutover on a lookalike cluster
   was withdrawn on 2026-11-23 — it had already run live, and a clone cannot prove the certificate store,
   which is the only part that breaks.

### Task 3: Prove the etcd restore and write the runbook

**Interfaces:**
- Consumes: the server from Task 2, and a snapshot from the restic repository that holds the servers'
  `etcd-snapshots` directory.
- Produces: a proven restore sequence, recorded in `docs/runbooks/restore-etcd.md`, that every rollback
  in this plan depends on.

**Done 2026-11-23, from a drill that ran on 2026-11-22.** Card #8 replaced that rehearsal with the
case that matters: a real snapshot, pulled out of the `nodes-streaming` restic stream
(`etcd-snapshot-streaming-1795348801`, 49 MB, taken 2026-11-22 12:00:01Z), restored into a
single-node `v1.31.14+k3s1` in a privileged container on the workstation under WSL2. Step 1 became
"pull the file from the bucket"; step 2 gained a requirement the rehearsal proved the hard way:
`--cluster-reset` reads the token from `--token`/`K3S_TOKEN` and not from the token file, and without
it the restore stops at `bootstrap data already found and encrypted with different token`. The reset
took 7 seconds, the restart 9–11 more, and 25 namespaces, 60 ArgoCD Applications and 376 Secrets were
read back, with `backup-restic`'s password byte-identical to the local copy.

**Why the snapshot comes from production.** A snapshot taken on the drill server proves only that an
empty cluster restores to empty. The question is whether a production snapshot comes back readable, so
the drill loads the newest one out of the repository.

## Rollback summary

| Step | Rollback |
|---|---|
| K3s minor | Re-run the installer with the previous version on that node; one node at a time |
| etcd unquorate | `--cluster-reset` from the newest snapshot, per `docs/runbooks/restore-etcd.md` — written and rehearsed on 2026-11-22, Task 3 |
| Traefik v3 | `helm rollback traefik` to the 2.11 revision. 2.11 reads both API groups, so the renamed resources keep working. Traefik v3 keeps the `acme.json` shape — `StoredData{Account, Certificates}` is byte-identical in v2.11 and v3.7 and the migration guide records no storage change — so 2.11 reads a store written by v3 without re-issuing. |
| Addon | Uninstall the repository release first, then remove `disable: [traefik]` and restart K3s, one node at a time. The addon and the release fight over the Service if both are installed. |
| `traefik-crd` release | Never `helm uninstall traefik-crd` while routes exist: its chart carries the `containo.us` CRDs and deletes every route with them. Delete its release secret to forget it, leaving the CRDs for the later delete step. |
