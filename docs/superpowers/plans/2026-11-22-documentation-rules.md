# Documentation rules and the two incident sections — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the documentation's rules mechanical — four page kinds, one home per fact, generated
pages that cannot drift — and rebuild Backups and Security as sections entered from an incident.

**Architecture:** Four small checkers under `hack/` share one entry point, `hack/check-docs.sh`.
`gen_docs.py` renders two pages from the repository (routes from `helm template`, the backup matrix
from the chart's values) and fails when the committed copy differs. `check_docs.py` proves nav
completeness, cited paths, the page banner, the application catalogue's set equality, and the absence
of secret-shaped values. `check_docs_staleness.py` prints pages older than their sources and never
fails. The pages themselves are prose; the checks are what keeps the prose honest.

**Tech Stack:** Python 3 standard library plus PyYAML; `helm` v4 for chart rendering; MkDocs Material
9.8.2 for the site; pytest (through `uv`) with `unittest`-style test classes, as `hack/tests/` does.

**Spec:** `docs/superpowers/specs/2026-11-22-documentation-rules-design.md`

## Global Constraints

- MkDocs Material **9.8.2**. Page bodies must render on GitHub too: blockquotes, never `!!!`
  admonitions.
- Checks run with **no cluster access**, like the rest of `hack/`.
- Markdown files are LF. Files under `cluster/argocd/**` keep CRLF and are never rewritten by this
  work.
- Tests run as
  `uv run --with-requirements hack/tests/requirements.txt python -m pytest -q hack/tests`.
- Plain language: a media or design term is glossed once, in plain words, the first time it appears
  in a page.
- No secret value ever: a page names a Secret, its key and where the value came from, never the
  value.
- A generated page carries `<!-- generated by hack/gen_docs.py; do not edit -->` as its first line,
  names its sources and its regenerate command, and carries **no timestamp**.
- A living page opens with one blockquote carrying **In one line**, **Use it when**, **Verified
  YYYY-MM-DD**, **Kind:** one of `explanation`, `how-to`, `reference`, `record`, and **Sources**.
- Gitmoji commit prefixes (`📝 docs:`, `🔧 chore:`, `🚀 feat:`, `🐛 fix:`).
- Never commit to `develop` or `main`; work stays on `feature/documentation-rules`.

## Review Focus

The failure modes the spec implies but no test names yet, most likely first. Each is pinned by a
test in the task that owns the code.

1. **A cited path with an anchor or a range.** Pages cite
   `docs/runbooks/restore.md#the-drill-log` and `cluster/helm/...`. The `references` check must strip
   a `#fragment` and tolerate Windows line endings, or it reports false failures on every citation
   that has one.
2. **A nav entry that is not a file.** `mkdocs.yml` entries are bare paths under `docs/`; a URL or a
   directory path in `nav:` must not be treated as a missing page.
3. **A route with no `Host(...)`.** `IngressRouteTCP`/`UDP` and a `web` redirect twin may carry no
   host or several matches; the parser must skip or split rather than drop a row silently.
4. **A chart `helm template` cannot render.** A wrapper chart without `charts/` throws. The generator
   must name the chart it skipped in its output and fail `--check` if that chart has a route file —
   never emit a page that silently omits an application.
5. **An existing page whose banner predates the five-line shape.** The banner check is diff-scoped;
   a page written before today must fail only when the change touches it, and the failure message
   must say which of the five lines is missing.
