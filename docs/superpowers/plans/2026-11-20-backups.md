# The homelab backup solution — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every stateful claim, PostgreSQL and etcd leaves the cluster nightly for one OVH bucket, with a Grafana page, one stale-stream alert, tested restores and a written coverage matrix.

**Architecture:** One bucket, four restic repositories (`nodes-nas`, `nodes-nuc0`, `nodes-streaming`, `nfs`) and one `cluster/helm/backup` chart. Each node job reads its `local-path` roots through a read-only `hostPath`, stages SQLite copies with Python's `backup()` API, and hands restic an explicit path list. The NFS job reads the `nas` exports directly. A weekly prune and a nightly verifier complete the set; K3s's own S3 etcd upload waits for W5, with an `etcd-local` restic bridge until then.

**Tech Stack:** Helm (one chart, no library), Python 3.12 standard library in ConfigMaps, restic 0.19.1, ArgoCD, kube-state-metrics 2.20, Grafana HTTP API, OVH Object Storage S3.

**Spec:** `docs/superpowers/specs/2026-11-20-backups-design.md`

## Global Constraints

- Bucket `ashudev-homelab-backup`, endpoint `s3.gra.io.cloud.ovh.net`, region `gra`, class 1-AZ Standard unless Task 1 measures more than 200 GB.
- Repositories: `nodes-nas`, `nodes-nuc0`, `nodes-streaming`, `nfs` — one restic repository each, created by hand **once**. No object this plan creates ever runs `restic init`.
- Every restic invocation carries `--retry-lock 2h`; the prune job carries `--retry-lock 6h`.
- Every CronJob sets `concurrencyPolicy: Forbid` and `startingDeadlineSeconds: 3600`.
- Every backup CronJob carries the label `homelab.io/backup-stream: <stream>`; the stream names are `nodes-nas`, `nodes-nuc0`, `nodes-streaming`, `nfs`, `prune`, `verify`.
- Retention: `--keep-daily 7 --keep-weekly 4 --keep-monthly 12 --prune`.
- Namespace `backup`; Secret `backup-restic` with `RESTIC_PASSWORD`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, read through `envFrom`.
- Never backed up: Plex media, the Stash library, the music export, qBittorrent downloads, Loki, Prometheus, `postgres-data`, `docs-site-site`.
- Every container sets memory requests and limits; CPU requests stay between 1m and 100m; no CPU limits.
- `cluster/argocd/**` files use CRLF line endings; everything else LF.
- YAML is 2 spaces, lowercase keys. Commit prefixes: `🚀` feature, `🐛` fix, `♻️` refactor, `📝` docs.
- Docs: quote-block header, nav entry in `mkdocs.yml` in the same change, repo paths in backticks, no jargon without a gloss.

## Review Focus

- **A row that resolves to nothing** (claim recreated with a new UID, namespace renamed, export removed) must fail the job with the row named — never upload an empty directory or a stale one.
- **A live SQLite database with a pending WAL** must be staged with committed rows intact, and the raw `-wal`/`-shm`/`-journal` files must never be what restic stores as the database.
- **A stream that succeeds while writing nothing** — a repository with zero snapshots, or a snapshot that stops advancing — must be reported broken by the verifier, not by silence.
- **A prune that meets a running backup's lock** must wait, and then fail loudly rather than skip the week.
- **Two directories matching one row** (a claim recreated, an old directory left behind) must raise, not pick one.

- [ ] **Step 5: Implement `prepare.py`**

Pinned signatures as built (the pre-flight added the `pv` pin and the row-level `exclude`):

```python
DEFAULT_DB_PATTERNS = ("*.db", "*.sqlite", "*.sqlite3")

class RowError(RuntimeError): ...

def resolve_claim(roots: list[pathlib.Path], namespace: str, claim: str, pv: str | None = None) -> pathlib.Path
def stage_databases(source: pathlib.Path, destination: pathlib.Path, patterns: Sequence[str] = DEFAULT_DB_PATTERNS,
                    exclude: Sequence[str] = ()) -> list[pathlib.Path]
def matches_any(relative: pathlib.Path, patterns: Sequence[str]) -> bool
def exclude_patterns(source: pathlib.Path, database_names: Sequence[str]) -> list[str]
def host_paths(candidates: Sequence[str]) -> tuple[list[str], list[str]]
def write_restic_inputs(rows: list[dict], staging: pathlib.Path, host_paths: Sequence[str] = ()) -> tuple[pathlib.Path, pathlib.Path]
def main(argv: list[str] | None = None) -> int   # --rows, --staging, --root (repeatable), --host-path (repeatable)
```

`resolve_claim` globs `<root>/*_<namespace>_<claim>` (the provisioner's `<pvName>_<namespace>_<pvcName>` directory) and requires exactly one match; a row carrying `pv` matches that PV exactly, which is how the two rows whose name collides with a released PV's directory stay unambiguous. `stage_databases` opens each match read-only through `file:<path>?mode=ro`, retries a plain open on `sqlite3.OperationalError` (the WAL fallback the design records), and copies with the `sqlite3` module's `backup()` — never `cp`; a file SQLite refuses to read raises `RowError` naming it, so one corrupt database does not abort the others silently. A database the row excludes (the *arr stack's `logs.db`) is not staged, because the row's exclusion is the one statement of what is not backed up. `write_restic_inputs` excludes **every** file matching a sqlite row's `db` patterns from the claim copy, staged or not, plus their `-wal`/`-shm`/`-journal` siblings: a live database must never be read raw. `host_paths` returns the candidates that exist and those that do not; a missing one is printed as `host-path missing: <path>` and never fails the run, because `/etc/netplan` does not exist on every node. `main` prints one line per staged file, plus `sqlite_version=<x>` so the first live run proves the module exists in the image.

Proven on the live cluster on 2026-11-20, inside a temporary pod mounting `/mnt/ssd0` read-only: a WAL database on a read-only mount opens with `mode=ro` and `backup()` produces an `integrity_check`-clean copy; the unpinned `calibre-web-automated-config` row refused to guess between the live directory and the released PV's; the pinned row resolved.

- [ ] **Step 4: Write the templates and `files/backup-node.sh`**

Helpers in `templates/_helpers.tpl`, used by every later task: `backup.repository <repo>` renders `s3:https://<endpoint>/<bucket>/<repo>`, `backup.labels <stream>` renders `app.kubernetes.io/name: backup` plus `homelab.io/backup-stream: <stream>`, and `backup.image` renders `<repository>:<tag>` for restic or python.

`configmap-rows.yaml` renders one ConfigMap per node holding `rows.json` (`{"stream": "nodes-<node>", "claims": [...]}`). `configmap-scripts.yaml` embeds `files/prepare.py` and `files/backup-node.sh` through `.Files.Get`. `cronjob-node.yaml` renders one CronJob per node:

- `nodeSelector: {kubernetes.io/hostname: <node>}`, `automountServiceAccountToken: false`, `restartPolicy: Never`, `activeDeadlineSeconds: 21600`, `backoffLimit: 1`.
- initContainer `prepare`: python image, `command: [python, /scripts/prepare.py]`, `args: [--rows, /config/rows.json, --staging, /staging]` plus one `--root` per root, one `--host-path` per entry in `hostPaths`, and `--host-path /host/etcd-snapshots` when the node sets `etcdSnapshots`. Mounts: the rows ConfigMap at `/config`, an `emptyDir` at `/staging` with `sizeLimit` from values, `/etc` read-only at `/host/etc` (one mount, so a node without `/etc/netplan` cannot fail the pod), every root read-only at its own absolute path, and `/var/lib/rancher/k3s/server/db/snapshots` read-only at `/host/etcd-snapshots` when enabled.
- container `restic`: `/bin/sh /scripts/backup-node.sh`, `envFrom: [secretRef: backup-restic]`, `RESTIC_REPOSITORY` from `backup.repository`, `STREAM`, `NODE`. Mounts: `/staging`, the roots read-only, `/scripts`, and the etcd snapshots mount when enabled.
- Both containers run as root (`runAsUser: 0`) with `allowPrivilegeEscalation: false` and all capabilities dropped; the chart comment says why — `hostPath` ignores `fsGroup`, so reading a claim another UID wrote needs the app's own UID or root. Every mount is `readOnly: true`; `/etc` is mounted as a directory rather than as four paths because a missing `hostPath` fails the pod, and `/etc/netplan` does not exist on every node.

`backup-node.sh`:

```sh
#!/bin/sh
set -eu
: "${RESTIC_REPOSITORY:?}" "${RESTIC_PASSWORD:?}" "${STREAM:?}" "${NODE:?}"
exec restic backup --retry-lock 2h --tag "stream=${STREAM}" --tag "node=${NODE}" \
  --exclude-file /staging/exclude.txt --files-from /staging/restic-paths.txt
```

`prepare.py` is what puts the host paths and the etcd snapshots into `/staging/restic-paths.txt`, printing `host-path missing: …` for the ones the node does not have. A job that backs up nothing still fails loudly: the row resolution raises before restic is ever called, and Task 6 counts snapshots independently.

`backup-nfs.sh`:

```sh
#!/bin/sh
set -eu
: "${RESTIC_REPOSITORY:?}" "${RESTIC_PASSWORD:?}" "${STREAM:?}"
while IFS='|' read -r tag path exclude; do
  [ -n "$tag" ] || continue
  [ -d "$path" ] || { echo "export missing: $path" >&2; exit 1; }
  set --
  for pattern in $exclude; do
    set -- "$@" --exclude "$pattern"
  done
  echo "path=$tag"
  restic backup --retry-lock 2h --host nas --tag "stream=${STREAM}" --tag "path=${tag}" "$@" "$path" </dev/null
done < /config/nfs-paths.txt
```

`--host nas` for the reason the node jobs carry it: restic otherwise names each snapshot after the pod, finds no parent and rereads the whole stream every night. `</dev/null` because the loop reads the path list from stdin, and a restic that inherited it would swallow the next export.

No `du` pass: walking a 200 GB library twice doubles the job's read time for a number the verifier's `restic stats` already reports per repository.

```python
STALE_AFTER = datetime.timedelta(hours=26)

def parse_time(value: str) -> datetime.datetime
def stream_line(name: str, snapshots: list[dict], bytes_used: int, now: datetime.datetime) -> str
def check_stream(name: str, snapshots: list[dict], bytes_used: int, budget_bytes: int, now: datetime.datetime) -> list[str]

def read_repository(repository: str, restic: str = "restic") -> tuple[list[dict], int]
def main(argv: list[str] | None = None) -> int
```

`parse_time` truncates the fractional part to six digits before `datetime.fromisoformat` and converts to UTC. `check_stream` returns `no snapshot`, `<x>h old (>26h)` formatted to one decimal, and `repository <a> over budget <b>` in GiB with one decimal. `read_repository` runs `restic -r <repo> snapshots --json --no-lock` and `restic -r <repo> stats --json --mode raw-data --no-lock`. `newest_etcd` filters `restic ls --json latest` entries to those under `/etcd-snapshots/` and returns the newest by `mtime`. `main` reads `/config/streams.json` (`[{"name": ..., "repository": ..., "budgetGiB": ..., "etcd": bool}]`), prints the stream line, prints `problem stream=<name> <text>` for each problem, and for `etcd: true` streams prints the `etcd …` line and applies `check_etcd`. Exit 1 when anything is wrong — including a control-plane stream whose copy is older than 26 hours, which is what makes the bridge in Task 3 provable rather than assumed. `main` takes `--restic` (default `restic`) so the suite can drive it against a stand-in script: three `MainTests` cover a healthy run, a stale one, and a repository restic cannot open — that last one must raise, because restic's error text on stderr is not an empty repository.
