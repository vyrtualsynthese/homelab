# Documentation site — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One internal hostname, `docs.kub.local`, serving every repository's `docs/` folder for
`main` and `develop`, rebuilt within a minute of a merge, with no commit to maintain and no GitHub
Actions minute spent.

**Architecture:** A CronJob runs a small Python builder that asks GitHub which branch heads moved,
downloads a tarball for each (repo, ref) that did, renders that repository's Markdown with MkDocs and
swaps the finished site into place. A separate unprivileged nginx Deployment serves the volume
read-only behind a LAN-only `IngressRoute`. Discovery is automatic: any repository under the owner
that has a `docs/` folder appears, without anything being added to this repo.

**Tech Stack:** Helm 4 chart, `squidfunk/mkdocs-material:9.8.1` (builder), MkDocs with the Material
theme, `nginxinc/nginx-unprivileged:1.31-alpine` (server), a `local-path` claim on `nuc0`, Traefik v2
CRDs, the GitHub REST API from a Python script using the standard library only.

**Spec:** `docs/superpowers/specs/2026-11-15-agent-work-tracking-and-docs-site-design.md` (§10, and
§11 for secrets, image policy and verification)

## Global Constraints

- One hostname, one route: `docs.kub.local` over TLS, matching every other `kub.local` app since
  2026-11-15. The TLS router on `websecure` sets `tls.options.name: internal-tls` in `kube-system`
  and **no** `secretName` and **no** `certResolver`, so the cluster's default certificate
  `kube-system/local-cert` serves it. A second `IngressRoute` on `web` redirects with
  `kube-system-lan-only` then `kube-system-redirect-to-https`.
- Middleware: `kube-system-lan-only@kubernetescrd` and nothing else. Internal only — no Authentik
  gate, no public hostname. `hack/check-exposure.sh` must pass.
- Only `main` and `develop` are built. Feature branches, tags and worktrees are out of scope.
- One build per (repo, ref), served at `/<repo>/<ref>/`. A ref with no `docs/` folder, or with no
  Markdown in it, contributes nothing — no empty site.
- A failed or partial build never replaces a working site. The previous build keeps serving and the
  index records the failure time.
- The builder holds a fine-grained GitHub token with `Contents: read` and `Metadata: read` only,
  from Secret `github-docs-ro` key `token` in namespace `docs`. No token is ever written to a file,
  a ConfigMap or a log line.
- Images: `squidfunk/mkdocs-material:9.8.1` and `nginxinc/nginx-unprivileged:1.31-alpine`, both
  pinned by tag. Both are Docker Hub; the spec records them as the §8.7 exception.
- `strategy: Recreate` for every stateful object, `nodeSelector: kubernetes.io/hostname: nuc0` for
  both workloads, memory request and limit on every container.
- The chart is self-contained (pattern A, no dependencies): there is no upstream chart for this.
- Files under `cluster/argocd/**` keep CRLF line endings.
- The builder has no cluster write access. Cluster-side steps are runbooks the operator executes.

## Review Focus

- **Polling that never triggers a rebuild.** GitHub returns `304` for an unchanged ref, and the
  script must read the stored ETag, not the response body. A wrong comparison either rebuilds
  everything every minute or nothing ever after the first run. Task 1 verifies both directions: a
  second run does no work, and a new commit does exactly one.
- **A private repository silently missing from the site.** The repository list is filtered by the
  token's own visibility. A token that cannot see a repo produces a site that looks complete. Task 6
  verifies with a throwaway private repo, and the index lists repositories the token could not read
  rather than omitting them.
- **A half-written site.** `mkdocs build` writes into its target directory; if it points at the live
  tree, readers see missing pages mid-build. Task 2 verifies the build lands in a staging directory
  and only a completed build is moved into place.
- **Path traversal through a repository name.** Repository names come from the API and become
  directory names. Task 2 rejects any name that is not `[A-Za-z0-9._-]+` before it is used as a path.
- **Two builds at once.** A merge during a build would have the second run overwrite the first.
  Task 4 sets `concurrencyPolicy: Forbid`, and the script tolerates being the one that loses.
- **A `--strict` build that fails on links outside `docs/`.** Repositories link to files that live
  elsewhere in the repo, so strict mode is left off unless a repository's own `mkdocs.yml` turns it
  on. Task 2 pins that rule.

### Task 1: Discovery and change detection

**Files:**
- Create: `cluster/helm/docs-site/files/build.py`

**Interfaces:**
- Consumes: environment `GITHUB_TOKEN`, `REPO_OWNER` (`vyrtualsynthese`), `REFS` (`main,develop`),
  `SITE_ROOT` (`/data/site`), `STATE` (`/data/state.json`), `FULL_REBUILD_AGE` (`86400`).
- Produces: `state` dict, persisted as JSON at `STATE`, shaped
  `{"refs": {"<repo>/<ref>": {"sha": "...", "etag": "...", "digest": "...", "built_at": "<iso8601>", "status": "ok|absent|failed", "detail": "..."}}, "last_full": "<iso8601|null>"}`.
  `digest` binds a stored `sha` to the `etag` it arrived with. Without it a corrupt or hand-edited
  `sha` is invisible: a `304` copies the stored sha back and compares it with itself, so the entry
  answers `skip` forever. An entry whose digest is missing or does not match is read **unconditionally**
  instead of trusted, which costs one full rebuild the first time a pre-digest state file is seen.
  `collect_plan(...) -> list[Decision]`, one `Decision(repo, ref, action, sha, etag, detail)` per
  (repo, ref) with one of four actions: `build` (fetch it, carrying the live sha), `skip` (the head
  is the one already built), `absent` (no such branch) or `failed` (the head check itself failed, with
  the first 400 characters of the reason); `fetch_tarball(repo, ref, workdir: Path) -> Path`
  returning the directory that holds the repository root.

- [ ] **Step 1: Write the repository listing**

`list_repos(owner: str) -> list[str]` calls
`GET https://api.github.com/user/repos?affiliation=owner&visibility=all&per_page=100&page=N`, following pages until
an empty page, and returns the `name` of every repository with `archived == false`. The `/user/repos`
form is required: `/users/{owner}/repos` answers with **public repositories only**, even when the
request is authenticated as that owner, so every private repository would vanish silently (measured
against the live API on 2026-11-16). It records, in
the state file under `"invisible"`, every name the API refused with `403`/`404` when queried later, so
the index can say "not readable by the token" instead of leaving a hole.

Header for every call: `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`,
`X-GitHub-Api-Version: 2022-11-28`, `User-Agent: docs-site-builder`.

- [ ] **Step 2: Write the head check**

`head_sha(repo: str, ref: str, etag: str | None) -> tuple[str | None, str | None, str | None]` calls
`GET https://api.github.com/repos/{owner}/{repo}/commits/{ref}` with `If-None-Match: <etag>` when one
is stored. It returns `(sha, new_etag, status)` where status is `"changed"`, `"unchanged"` (HTTP 304),
or `"absent"` — and `absent` is **422** (`No commit found for SHA`) or **409** for an empty repository,
not 404, as the live API answered on 2026-11-16. A `304` counts nothing against the rate limit,
which is the whole reason this is a conditional request.

- [ ] **Step 3: Write the tarball fetch**

`fetch_tarball(repo, ref, workdir)` downloads
`https://codeload.github.com/{owner}/{repo}/tar.gz/refs/heads/{ref}` with the token header, extracts
it with `tarfile` (mode `r:gz`), and strips the single top-level directory GitHub adds. Use `codeload`,
not the API tarball URL, so there is no redirect to reason about.

Reject any `repo` that does not match `^[A-Za-z0-9._-]+$` before it is used as a path, and refuse to
extract a member whose resolved path leaves the work directory.

- [ ] **Step 4: Write the entry point and the dry run**

`main()` builds the plan: list repos, for each `(repo, ref)` call `head_sha`, and build when the sha
differs from the stored one, when the stored status is `absent` and the ref now exists, or when
`now - last_full > FULL_REBUILD_AGE`. `--dry-run` prints one line per pair — `build homelab/develop
<sha>` or `skip homelab/develop` — and writes nothing. `--full` ignores the age check. `--repo NAME`
restricts the run to one repository.

- [ ] **Step 5: Prove both directions against the live API**

```bash
export GITHUB_TOKEN=$(grep GITHUB_PERSONAL_ACCESS_TOKEN ~/.config/opencode/keys.env | cut -d= -f2-)
export SITE_ROOT=/tmp/docs-site STATE=/tmp/docs-state.json FULL_REBUILD_AGE=86400
python3 cluster/helm/docs-site/files/build.py --dry-run
python3 cluster/helm/docs-site/files/build.py --dry-run
```

Expected: the first run prints `build` for each ref that exists; the second prints `skip` for every
one of them. Then push any commit to `develop` in a scratch repository and confirm exactly one line
flips back to `build`.

- [ ] **Step 6: Commit**

```bash
git add cluster/helm/docs-site/files/build.py
git commit -m "🚀 feat(docs-site): repository discovery and branch-head change detection"
```

### Task 2: Build one site, atomically

**Files:**
- Modify: `cluster/helm/docs-site/files/build.py`
- Create: `cluster/helm/docs-site/files/mkdocs.yml.tpl`

**Interfaces:**
- Consumes: `fetch_tarball` from Task 1.
- Produces: `build_site(repo: str, ref: str, src: Path, site_root: Path, work_root: Path) -> None`,
  which leaves `<site_root>/<repo>/<ref>/index.html` in place and raises `BuildError(detail)` on
  failure.

  **Nothing transient may live under `site_root`.** nginx serves that directory as its document root
  with no auth and no index filtering, so a checkout or a staging tree left there is downloadable by
  anyone on the LAN — including a private repository's whole tree, `keys.json` and all. Work and
  staging directories live under `work_root` (default `<site_root>/../work`), which nginx never sees.
  This is the fix for the exposure the Task 1 re-review found: `.work` used to sit under `site_root`
  and was reachable during a build.

- [ ] **Step 1: Write `mkdocs.yml.tpl`**

A template with three substitutions — `{{site_name}}`, `{{docs_dir}}`, `{{site_dir}}` — and this
body:

```yaml
site_name: "{{site_name}}"
docs_dir: "{{docs_dir}}"
site_dir: "{{site_dir}}"
use_directory_urls: true
theme:
  name: material
  features: [navigation.sections, navigation.top, content.code.copy]
  palette:
    - scheme: slate
markdown_extensions:
  - admonition
  - attr_list
  - tables
  - toc: {permalink: true}
  - pymdownx.superfences:
      custom_fences:
        - name: mermaid
          class: mermaid
          format: !!python/name:pymdownx.superfences.fence_code_format
plugins: [search]
```

No `nav:` key: MkDocs derives navigation from the file tree, so an agent adding a page needs no edit
anywhere.

- [ ] **Step 2: Write `build_site`**

1. If the checkout contains `mkdocs.yml` at its root, use it verbatim — a repository owns its own
   documentation. Otherwise render the template into `<workdir>/mkdocs.yml`.
2. Build into `<work_root>/.staging/<run_id>/<repo>__<ref>/` with
   `subprocess.run(["mkdocs", "build", "-f", config, "-d", staging, "--quiet"], check=True)`, capturing
   stderr into `BuildError.detail`.
   The per-run `<run_id>` level is what keeps two concurrent runs from writing into one staging tree.
3. Only on success: remove `<site_root>/<repo>/<ref>` if present, then `os.replace(staging, target)`.
   Create the parent directory first. `--strict` is never passed; where a repository wants it, its own
   `mkdocs.yml` sets `strict: true`.
4. On failure, leave the staging directory in place under `.failed/` for one run, so the detail can be
   read, and re-raise.
5. Before publishing, guarantee `<staging>/index.html`. Most documentation roots hold no
   `index.md`/`README.md` — `MkDocs` then writes no page at the site root, so the route
   `/<repo>/<ref>/` answers 403 and `published_missing` reads a good site as lost and rebuilds it on
   every run (measured: 9 of 10 published pairs rebuilt on the second live pass). A site that ships
   its own index keeps it untouched; otherwise the builder writes a plain landing page listing the
   site's pages, marked `docs-site-landing`.

- [ ] **Step 3: Wire it into `main()`**

For each planned pair: fetch, check `docs/` exists and contains at least one `*.md`, and on either
failure record `status: "absent"` (no docs) or `status: "failed"` (with the first 400 characters of
the error) in the state, then continue with the next pair. One repository's breakage never stops the
run. The process exits `0` unless writing the state file or swapping failed, so a Kubernetes Job does
not retry a run that was mostly fine.

- [ ] **Step 4: Prove it renders, and prove a failure does not clobber**

```bash
python3 cluster/helm/docs-site/files/build.py --repo homelab
ls /tmp/docs-site/homelab/develop/index.html
grep -c 'docs.kub.local\|Homelab' /tmp/docs-site/homelab/develop/index.html
```

Then break it on purpose: put a `mkdocs.yml` with an invalid key at the root of a scratch repo,
point `--repo` at it, run again, and confirm the previous `develop` site is still served byte for
byte and the state records `status: "failed"`.

- [ ] **Step 5: Commit**

```bash
git add cluster/helm/docs-site/files
git commit -m "🚀 feat(docs-site): render a repository's docs into a staged site"
```

### Task 3: The index page

**Files:**
- Modify: `cluster/helm/docs-site/files/build.py`

**Interfaces:**
- Consumes: the state file written by Task 2.
- Produces: `<site_root>/index.html`, regenerated at the end of every run, including the first one
  before any site exists.

- [ ] **Step 1: Write `write_index(site_root: Path, state: dict) -> None`**

One static HTML page, no JavaScript, no assets, listing every `(repo, ref)` from the state sorted by
repository then ref. One row per pair with: a link to `/<repo>/<ref>/`, the `built_at` date, and a
status word — `built`, `no docs on this ref`, `build failed: <detail>`, or `not readable by the token`.
A pair whose status is not `ok` has no link. The page says when it was generated and names the
schedule, so a stale page explains itself. The schedule is env `SCHEDULE` (`* * * * *` by default),
which Task 4 passes from the chart's values: the page must not claim a cadence the CronJob does not
run on.

- [ ] **Step 2: Call it at the end of every run**

After the build loop and after the state is persisted, so a crash mid-run leaves the previous index
intact.

Expected: a row for `homelab/develop` linking to the built site; `homelab/main` either absent

- [ ] **Step 2: Write the builder ConfigMap**

- [ ] **Step 3: Write the CronJob**

`schedule` from values, `concurrencyPolicy: Forbid`, `startingDeadlineSeconds: 55`,
`successfulJobsHistoryLimit: 3`, `failedJobsHistoryLimit: 3`. Pod: `restartPolicy: Never`,
`backoffLimit: 0`, `activeDeadlineSeconds: 900`, `nodeSelector` from values. One container from

/tmp`, the token from the Secret as `GITHUB_TOKEN` via `secretKeyRef`, and `SITE_ROOT=/data/site`,
`STATE=/data/state.json`, `REPO_OWNER`, `REFS`, `FULL_REBUILD_AGE` and `SCHEDULE` (from `schedule`,
so the index page names the cadence the CronJob actually runs at) from values. Security context:
`allowPrivilegeEscalation: false`, `capabilities: {drop: [ALL]}` — no `runAsNonRoot`, because the
image has no non-root variant and writes only to its mounts.

- [ ] **Step 4: Write the PVC, the two ConfigMaps, the Deployment and the IngressRoute**

PVC `<fullname>-site`, `ReadWriteOnce`, size and class from values.
`configmap-nginx.yaml` carries an `nginx.conf` with `listen 8080;` and `root /data/site;` (the root
need not exist at mount time).
Deployment: one replica, `strategy: Recreate`, `nodeSelector` from values, the claim at `/data`, an
`initContainer` from the same nginx image that runs `mkdir -p /data/site` and writes a placeholder
`index.html` only when none exists, so the probe passes before the first build. The init container
runs as root and the nginx container does not: a `local-path` claim is created and left root-owned by
the builder, so only root can create the directory, while nginx runs as uid 101 with
`runAsNonRoot: true`. Then the nginx container with the claim mounted read-only at `/data`, the nginx
configmap mounted at `/etc/nginx/conf.d` read-only, `readOnlyRootFilesystem: true`, `/tmp` on an
`emptyDir`, `allowPrivilegeEscalation: false`, `capabilities: {drop: [ALL]}`, readiness and liveness
`httpGet /` on port `8080`. The two `IngressRoute` objects follow
`cluster/helm/vikunja/templates/ingressroute.yaml`, which is the freshest working copy of the
TLS-plus-redirect shape: one router on `websecure` with `tls.options`, one on `web` with `lan-only`
then `redirect-to-https`.

### Task 5: Token and first run

**Files:**
- Create: `docs/runbooks/docs-site-first-run.md`

**Interfaces:**
- Consumes: the chart from Task 4.

- [ ] **Step 1: Create the token**

On GitHub: Settings → Developer settings → Fine-grained tokens → New token. Resource owner
`vyrtualsynthese`, repository access "All repositories", permissions `Contents: Read-only` and
`Metadata: Read-only`. Nothing else. Note the expiry date in the runbook.

- [ ] **Step 2: Write the runbook**

1. `kubectl create namespace docs`
2. `kubectl -n docs create secret generic github-docs-ro --from-literal=token=<token>`
3. Wait for the Application to report `Synced`/`Healthy`.
4. `kubectl -n docs get pods` → the nginx pod `Running 1/1`.
5. `kubectl -n docs create job --from=cronjob/docs-site-build docs-first-1` then
   `kubectl -n docs logs job/docs-first-1` → one line per (repo, ref) with `build`, `skip` or
   `absent`, and no traceback.
6. `curl -skI https://docs.kub.local/` → `200`.
7. `curl -sk https://docs.kub.local/homelab/develop/ | head -20` → the Material page.
8. Rotation: create the new token, patch the Secret, delete the Job so the next run uses it.
9. Rollback: delete the Application and the namespace. The claim holds only rebuildable output, so
   nothing is lost except one build cycle.

- [ ] **Step 3: Operator executes it and pastes 4, 5 and 7 back**

- [ ] **Step 4: Commit**

